## 4분면 매트릭스

| :----: | :---- | :---- |

## 토폴로지별 선택 기준

### 01. Centralized — 중앙 코디네이터
- **언제 쓰나:** 단순한 라우팅이 충분할 때, 워크플로우가 정형적일 때
- **장점:** 단순함, 디버깅 쉬움
- **단점:** SPOF, 코디네이터가 병목
- **대표:** 단일 슈퍼바이저 + 워커 N개

### 02. Hierarchical — 슈퍼바이저 위임
- **언제 쓰나:** 작업이 회사 조직처럼 자연스럽게 계층화될 때 (조직형 자동화)
- **장점:** 책임 경계 명확, 권한 위임 자연스러움
- **단점:** 깊은 계층은 지연 증가, 토큰 폭증 위험
- **대표:** **CrewAI**, MetaGPT (소프트웨어 회사 조직 시뮬)

### 03. Peer-to-Peer — 수평 협업
- **언제 쓰나:** 동등한 전문가들이 협상해야 할 때, 합의가 필요할 때
- **장점:** 단일 장애점 없음, 분산
- **단점:** 합의 비용, 결정 지연
- **대표:** 토론·합의형 multi-agent

### 04. Blackboard — 공유 메모리
- **언제 쓰나:** 비동기 협업, 약결합이 필요할 때, 누가 무엇을 할지 미리 정하기 어려울 때
- **장점:** 유연함, 에이전트 추가/제거 쉬움
- **단점:** 일관성 관리 어려움, 누가 책임지나 불명확
- **대표:** 공유 작업 공간 패턴

### 05. Market-Based — 입찰·계약
- **언제 쓰나:** 자원 할당이 필요할 때, 경쟁적 의사결정
- **장점:** 시장 원리로 효율 자동 조정
- **단점:** 설계 복잡도 높음, 구현 사례 적음
- **대표:** 계약망 프로토콜

### 06. Swarm — 자기조직화
- **언제 쓰나:** 대규모 병렬, 단순한 규칙으로 복잡한 행동 창발 필요
- **장점:** 확장성 최강
- **단점:** 예측 불가, 디버깅 거의 불가능
- **대표:** 군집 시뮬레이션

### 07. Graph / DAG — 의존성 그래프
- **언제 쓰나:** 작업 의존성이 명확하고 복잡할 때, 부분 실패 재시도가 필요할 때
- **장점:** 흐름 시각화 가능, 부분 재실행
- **단점:** 사전 정의 필요, 동적 흐름 약함
- **대표:** **LangGraph**, Airflow 스타일

### 08. Hybrid — 4분면 가로지름 (실무 표준 ★)
- **언제 쓰나:** 거의 모든 엔터프라이즈 운영
- **장점:** 강한 코어 + 분산 실행의 결합
- **단점:** 의도적 설계 필요 (우연이면 안 됨)
- **대표:** LangGraph 실 운영, Manus, 엔터프라이즈 스택

## 의사결정 트리

```
사용자 요청이 정형적인가?
├─ YES: Centralized 또는 DAG
│   └─ 의존성이 복잡한가?
│       ├─ YES → 07 DAG (LangGraph)
│       └─ NO  → 01 Centralized
│
└─ NO: 비정형 / 협업 필요
    ├─ 작업이 자연스럽게 계층화되나?
    │   └─ YES → 02 Hierarchical (CrewAI)
    │
    ├─ 비동기·약결합 필요?
    │   └─ YES → 04 Blackboard
    │
    ├─ 동등한 전문가의 합의 필요?
    │   └─ YES → 03 P2P
    │
    └─ 위 모두 부분적으로 필요?
        └─ YES → 08 Hybrid (실무 표준)
```

## "에이전트 vs 도구" 절제 원칙 (강의 17·20번)

**경고:** 토폴로지 선택 전에 다음을 확인.

> "도구를 나누는 것 ≠ 에이전트를 나누는 것. 후자만 절제한다."

- 도구는 풍부하게 (제한 없음)
- 에이전트는 보수적으로:
  - 책임 경계가 명확히 분리되는가?
  - 도구로 처리하면 안 되는 이유가 있는가?
  - 정말 별개의 인지 루프가 필요한가?

3개 이상 답이 No면 → 에이전트를 추가하지 말고 도구만 추가.

## 산출물 생성 시 적용

   - 01·07 → `langgraph-skeleton.py`
   - 02 → `crewai-skeleton.py`
   - 단일 코어 (Strong Single) → `claude-tool-use-skeleton.py`

   - 01·07·Hybrid → 단일 페르소나
   - 02 → Manager + Worker 페르소나 분리
